# scrcpy LAN

基于 [scrcpy](https://github.com/Genymobile/scrcpy) 的社区 fork，新增使用 [mygo](https://github.com/egoist/mygo) 原生 Go UI 的局域网投屏启动器。初版面向 Windows 10 / 11 x64，界面使用 Direct3D 11 绘制，不需要浏览器、WebView2、Node.js 或额外安装 Go。

## 下载和启动

从 [v0.4.0 Release](https://github.com/KevinChen222/scrcpy/releases/tag/gui-v0.4.0) 下载 `scrcpy-lan-v0.4.0-windows-x64.zip`。**完整解压**便携包，双击 `scrcpy-lan.exe`。`runtime` 目录附带官方 scrcpy v5.0、adb 和运行依赖，勿单独移动 exe。发布包未进行代码签名。

GUI 用于设备发现、配对和档位选择；视频、声音和键鼠控制由原版 scrcpy 在独立投屏窗口中处理。关闭 GUI 会停止它启动的投屏，不会关闭全局 ADB 服务。

可选择「画面和声音」（默认）或「仅音频」。仅音频不打开投屏窗口，在 GUI 中点击「停止音频」结束；关闭 GUI 也会停止音频会话。

## 窗口控制

GUI 使用系统标题栏的最小化、最大化 / 还原和关闭按钮，操作台内不再重复放置这些按钮。可以拖动窗口边缘调整大小；初始窗口会适配当前桌面可用空间，避免高 DPI 下按钮超出屏幕。GUI 按 F11 切换全屏，Esc 退出全屏；配对弹窗打开时 Esc 优先关闭弹窗。

设备列表、手动连接和首次配对集中在左侧窄栏。较宽窗口中，右侧的档位和播放设置并排显示；缩小窗口后自动改为纵向排列。左右区域独立滚动，底部开始 / 停止按钮始终可见。

投屏默认以带标题栏的普通窗口启动，可拖动、缩放、最小化和关闭。勾选「投屏启动时全屏（覆盖任务栏）」可直接进入真正全屏模式。投屏窗口按 F11 切换全屏 / 普通窗口，Esc 退出全屏，Alt+Q 关闭投屏。Esc 退出全屏仅作用于本程序启动且当前获得焦点的投屏窗口；普通窗口中 Esc 保留 scrcpy 的手机返回操作。最大化只占桌面工作区，会保留任务栏，要覆盖任务栏请使用全屏。

默认保持手机画面比例，因此手机与电脑比例不同时会留边。勾选「铺满屏幕（拉伸画面）」可以填满电脑画面，但会改变画面比例。窗口启动设置在下一次投屏时生效。

## 设备熄屏与电脑键盘输入

勾选「启动后熄灭设备屏幕（关闭屏幕电源）」后，使用 scrcpy 的 `--turn-screen-off` 关闭手机显示屏电源，同时继续传输画面和声音、接受电脑操作。这是真正的设备屏幕电源控制，不修改屏幕亮度，也不显示黑色遮罩。默认不勾选；无线、USB 和仅音频均可使用。投屏窗口按左 Alt+O 熄屏，左 Alt+Shift+O 亮屏；手机实体电源键仍会亮屏。设备需已授权，部分厂商可能限制屏幕电源控制。[scrcpy 设备屏幕控制说明](https://github.com/Genymobile/scrcpy/blob/v5.0/doc/device.md#turn-screen-off)

勾选此项的会话结束后自动请求重新亮屏，包括点击停止、关闭投屏窗口、投屏异常退出和关闭 GUI。退出清理会等待亮屏恢复操作完成；若设备断线，GUI 会提示恢复失败。若逻辑唤醒后物理屏幕仍关闭，会重新应用休眠 / 唤醒状态，手机可能显示锁屏。

默认启用「电脑键盘输入（UHID，支持手机输入法）」，通过 `--keyboard=uhid` 模拟实体键盘。点击电脑投屏画面中的手机输入框，然后直接用电脑键盘打字；中文使用**手机上的输入法**组合和选词。首次可在投屏窗口按左 Alt+K 打开手机实体键盘设置，选择与电脑一致的键盘布局，并配置支持实体键盘的中文输入法。电脑输入法已组合好的中文可复制后按左 Alt+V 粘贴到手机输入框。[scrcpy 键盘说明](https://github.com/Genymobile/scrcpy/blob/v5.0/doc/keyboard.md#uhid)

UHID 可用于无线和 USB。旧设备若出现 UHID 权限 / 不支持错误，停止投屏后取消勾选，恢复 scrcpy 基础 SDK 键盘输入（主要支持 ASCII 等有限字符），仍可通过左 Alt+V 粘贴中文。仅音频模式不启用电脑键盘，也不显示窗口设置。

## USB 有线模式

1. 用支持数据传输的 USB 线连接手机与电脑，在手机开发者选项中开启「USB 调试」，解锁并允许电脑调试授权。
2. GUI 选择「USB 有线」，点击「重新扫描」，选择 USB 设备；无需无线配对，也不要求同一 Wi-Fi。
3. 默认选择「有线高规格 · 120 fps」：设备原生分辨率、最高 120 fps、40 Mbps。也可使用流畅、均衡、高清、原画或自定义档位。若手机编码器不支持高规格或播放不稳定，请选较低档位。

有线模式只查找 USB 设备，不进行局域网端口扫描。列表中的「请在手机上授权」或「离线」需要先处理手机授权 / 连接。切换连接方式或插入数据线后，请重新扫描。

## Android 11 及以上

1. 手机和电脑连接同一个 Wi-Fi，手机开启「开发者选项 → 无线调试」。
2. 首次使用，手机进入「使用配对码配对设备」。GUI 点击「重新扫描」，选择发现的配对服务，或点击「打开配对」，在弹窗里填写配对页面的 IP:端口和 6 位配对码，点击「配对设备」。
3. GUI 选择「无线 / 局域网」。配对成功后，选择连接服务和投屏档位，点击「开始投屏」。USB 设备在「USB 有线」模式中显示。
4. 如果路由器阻止 mDNS，使用「手动连接」，填写**无线调试主页**上的 IP:端口。这个连接端口与配对码页面的配对端口不同，切换无线调试后也可能变化。

手机必须开启无线调试并允许连接；程序无法发现或投屏未开启 ADB 的普通局域网手机。Windows 提示网络访问时需允许 adb 在私人网络中通信。访客 Wi-Fi、AP 隔离、VPN 或防火墙可能阻止发现 / 连接。[Android 官方无线调试说明](https://developer.android.com/tools/adb#wireless-android11-command-line)

## Android 10 及以下 / 旧版 ADB

首次需要 USB 连接并在手机上授权 USB 调试。在此目录的终端执行：

```powershell
.\runtime\adb.exe devices
.\runtime\adb.exe -s 手机序列号 tcpip 5555
```

确认手机和电脑在同一 Wi-Fi，拔掉 USB，GUI 扫描本地网段或手动输入手机 IP（默认 5555）。扫描采用最多 32 个并发连接、每个 250ms 超时，仅探测所选 IPv4 网段的 TCP 5555 端口。大于 /24 的本地网络只扫描电脑所在 /24，其他网段可手动连接。开放端口仅标为「待验证」，启动投屏时会检查真实 ADB 连接和授权状态。

## 投屏档位

| 档位 | 分辨率长边上限 | 帧率上限 | 视频码率 |
| --- | ---: | ---: | ---: |
| 流畅 | 1024 px | 30 fps | 2 Mbps |
| 均衡（默认） | 1600 px | 60 fps | 6 Mbps |
| 高清 | 1920 px | 60 fps | 12 Mbps |
| 原画 | 设备原生分辨率 | 60 fps | 20 Mbps |
| 有线高规格（USB 默认） | 设备原生分辨率 | 120 fps | 40 Mbps |

统一采用兼容性较好的 H.264。帧率为上限，实际帧率由内容刷新、设备编码能力和连接带宽决定；120 fps 需要手机屏幕、内容和编码器支持。档位在启动投屏时应用，切换需先停止再启动。同时运行一个投屏会话；Android 11+ 支持音频转发。

无线和 USB 均可选择「自定义」，填写分辨率长边（整数 0–65535 px，0 为原生分辨率）、帧率上限（整数 1–65535 fps）和视频码率（整数 1–2147 Mbps）。这些范围是参数校验范围，手机不一定支持其中的高规格值。两种连接方式各自保留本次程序运行中的自定义值；关闭程序后恢复默认值。输入无效时会提示错误，不启动投屏。

## 仅音频模式

选择「仅音频」后，视频捕获和投屏窗口关闭，只将手机系统声音转发到电脑。音频编码可选择：

| 编码 | 适用场景 | 码率设置 |
| --- | --- | --- |
| Opus（默认） | 日常播放，兼顾音质和带宽 | 64 / 128（默认）/ 192 / 256 / 320 Kbps，或自定义 |
| AAC | 设备不支持 Opus 时的兼容选择 | 相同预设与自定义 |
| FLAC | 音质优先，无损压缩 | 不适用，自动隐藏 |
| RAW | 未压缩 PCM，占用更多带宽 | 不适用，自动隐藏 |

自定义音频码率允许整数 6–9000 Kbps，按原值传递给 scrcpy。**这是 GUI 的请求范围，不代表编码器能输出该码率**；过高值可能被设备限制或拒绝。Opus 有自身码率范围，提高请求到 9000 不会将其变成无损编码；追求音质可选 FLAC。FLAC 不提高原始音频采集规格，也不能恢复源音频已损失的细节。[Opus 编码器说明](https://opus-codec.org/docs/opus_api-1.5/group__opus__encoderctls.html)

输入无效时提示错误，不启动会话。音频编码、档位和自定义值在本次运行中保留；切换模式不会丢失。选择 FLAC / RAW 时忽略保留的码率输入。

点击「开始音频」启动，「停止音频」结束。仅音频不校验或传递视频档位，也不应用全屏、拉伸或键盘设置；若勾选熄屏，保留屏幕电源控制通道。声音采集失败时会结束并在 GUI 显示错误详情。[scrcpy 音频说明](https://github.com/Genymobile/scrcpy/blob/v5.0/doc/audio.md)

音频转发需 Android 11+；Android 11 启动前必须解锁手机，Android 10 及以下不支持。默认转发系统输出并停止手机本地声音播放。部分受保护内容或厂商限制可能无法采集；压缩编码需手机支持对应编码器。

## 音视频缓存

无线和 USB 的所有档位都可选择「关闭缓存」、0.5 秒、1 秒、2 秒（默认）或「自定义缓存」。自定义单位为**秒**，支持 0–60 秒、最多三位小数，例如 `1.735` 秒；0 关闭额外缓存。界面按秒显示，GUI 转换成整数毫秒后传递给 scrcpy。

启用时，画面和声音使用相同的缓存目标，通过 scrcpy 的 `--video-buffer` 和 `--audio-buffer` 吸收短时传输抖动；键鼠操作会立即发送，但看到操作结果也会有相应延迟。关闭时不添加这两个参数，使用 scrcpy 默认的低延迟播放及必要音频缓冲。切换缓存需停止后重启投屏。缓存选择和自定义值在本次运行中的不同模式间保留。

仅音频模式使用相同缓存选择，只传递音频缓存参数；关闭额外缓存时保留 scrcpy 默认的必要音频缓冲。

缓存不能弥补持续带宽不足、断线、手机编码或电脑解码性能不足，也不能保证所有场景零掉帧。遇到持续卡顿，请先降低档位；原生高分辨率、高帧率和长缓存也会增加电脑内存用量。

## 实时日志

点击底部「打开日志窗口」打开独立窗口，实时显示 GUI 操作、ADB 输出、scrcpy 信息和错误。窗口打开时启动的投屏会启用 scrcpy 详细诊断；运行中打开也能立即收集此后的标准输出和错误。重复点击会聚焦已有窗口。

平时不收集日志，不创建日志文件；关闭日志窗口立即停止收集并清空，重新打开从当前时刻开始。窗口仅在内存保留最近 64 KiB，自动跟随新内容，向上滚动可查看已有内容，支持选择复制。配对码会隐藏。关闭 GUI 会一并关闭日志窗口。出错时可打开日志窗口后重试，查看完整诊断。

## 同步上游

GUI 位于独立的 `gui/` Go 模块，使用官方 scrcpy 命令行参数与 ADB；没有修改上游 `app/` 或 `server/`。正常上游更新可以通过 GitHub「Sync fork」或合并 `upstream/master` 同步，保留 GUI 附加目录和工作流即可。

便携包仍固定官方运行包版本和 SHA-256。要将新版 scrcpy 一并打包，更新 `gui/build.ps1` 中的版本与官方校验值及相关说明，并运行 GUI 测试和便携包验证。若上游删除或改变参数 / 行为，再适配 GUI；不要为了 GUI 版本号修改上游核心版本。

## 从源码构建

需要 Go 1.27.1+ 和 PowerShell 7。mygo 固定在 `869768d02d9154d5b2f9f3a6ebb39767f8f96983`，投屏运行包固定为官方 scrcpy v5.0 并检查 SHA-256。

```powershell
cd gui
go test ./...
go vet ./...
.\build.ps1 -GuiVersion v0.4.0
```

输出为 `gui/build/scrcpy-lan-v0.4.0-windows-x64.zip` 和对应 `.sha256`。构建脚本会验证测试、使用 `CGO_ENABLED=0` 编译并移除原生 UI 调试检查器，然后附带运行文件和许可证。开发时可将 `runtime` 放到开发版 exe 旁，或把 adb / scrcpy 加入 PATH。

测试覆盖 mDNS / ADB 解析、服务去重、地址及配对码校验、拒绝未授权连接、子进程参数和取消，以及原生界面的设备 / 档位选择。真实手机投屏仍需在自己的局域网和手机上验证。

需要验证真实 Windows 窗口控制时，可在解锁的桌面设置 `$env:SCRCPY_GUI_NATIVE_TEST = '1'` 后运行 `go test -buildvcs=false -v .`。该检查使用程序自身 mygo API 验证缩放、最小化、最大化、全屏边界和还原，完成后自动退出；常规测试不打开窗口。运行普通测试前清除这个环境变量。

需要验证独立投屏窗口时，将便携包的 `runtime` 加入 PATH，设置 `$env:SCRCPY_GUI_MIRROR_NATIVE_TEST = '1'` 和 `$env:SCRCPY_GUI_NATIVE_SERIAL = '已授权设备序列号'` 后运行 `go test -buildvcs=false -count=1 -v .`。该检查使用真实手机，验证自定义参数、关闭 / 2 秒 / 3 秒缓存、普通窗口和全屏启动、Esc 还原标题栏与 F11 往返切换，完成后仅停止测试创建的会话。运行普通测试前清除这些测试环境变量。

新会话验证：设置 `$env:SCRCPY_GUI_DEVICE_TEST_SERIAL = '已授权设备序列号'`，运行 `go test -buildvcs=false -count=1 -run TestLiveDeviceScreenRestoreAndAudio -v .`，检查四种音频编码、0.5 秒缓存和停止 / 退出 / 异常退出后的物理亮屏。此测试会改变测试机屏幕状态并留下亮屏；9000 Kbps 能否启动依编码器而定，成功初始化不能证明实际输出为 9000 Kbps。

日志窗口原生验证：设置 `$env:SCRCPY_GUI_LOG_NATIVE_TEST = '1'` 后运行 `go test -buildvcs=false -count=1 -v .`，检查实时显示、关闭清空与重新打开。运行普通测试前清除对应环境变量。
